# Retail A/B case

Синтетический офлайн-кейс для оценки продуктового и статистического мышления аналитиков данных. Рабочее время участника — 60 минут; короткая защита проводится отдельно.

## Состав проекта

```text
2026.08.20_offline_retail_ab_case/
├── PARTICIPANT_BRIEF.md
├── README.md
├── requirements.txt
├── data/
│   ├── retail_ab_case.sqlite
│   └── csv/
│       ├── transactions.csv
│       ├── transaction_items.csv
│       ├── products.csv
│       ├── stores.csv
│       ├── weather_daily.csv
│       └── promotions.csv
├── notebooks/
│   └── starter.ipynb
├── outputs/
├── scripts/
│   └── generate_data.py
└── organizer/
    ├── ANSWER_KEY.md
    ├── SCORING_RUBRIC.md
    ├── reference_analysis.py
    ├── reference_results.json
    ├── qc_summary.json
    └── case_overview.xlsx
```

Все данные синтетические; реальных покупателей, магазинов и коммерческих показателей в них нет.

## Что выдавать участнику

В пакет участника входят:

- `PARTICIPANT_BRIEF.md`;
- этот `README.md`;
- `requirements.txt`;
- каталог `data/`;
- `notebooks/starter.ipynb`.

Каталоги `organizer/` и `scripts/` участнику **не передаются**: в них находятся закрытые ответы и логика генерации данных.

## Варианты работы с данными

Один и тот же набор доступен в двух форматах:

- `data/retail_ab_case.sqlite` — для SQL;
- `data/csv/*.csv` — для Python, R, Excel и BI-инструментов.

В SQLite названия таблиц совпадают с именами CSV-файлов без расширения.

Для быстрого старта можно открыть `notebooks/starter.ipynb`. Ноутбук только подключает библиотеки, показывает доступные файлы и примеры чтения; способ анализа участник выбирает самостоятельно.

## Краткий словарь таблиц

| Таблица | Гранулярность | Назначение |
|---|---|---|
| `transactions` | один чек | магазин, время, статус и итоговая сумма чека |
| `transaction_items` | одна товарная строка чека | товар, количество, цена, скидка и сумма позиции |
| `products` | один товар | наименование, категория, подкатегория и атрибуты товара |
| `stores` | один магазин | город (во всех строках Москва), формат, экспериментальная группа и matched pair |
| `weather_daily` | одна дата | ежедневная погода в Москве, общая для всех магазинов |
| `promotions` | промо × магазин × товар | период и параметры промо |

Названия и типы полей можно посмотреть непосредственно в CSV или через схему SQLite. Поля намеренно описаны кратко: исследование гранулярности, ключей и качества источников является частью задания.

Обратите внимание: «трафик» в контексте кейса означает число завершённых чеков. Данных о входящем потоке посетителей и конверсии в покупку нет.

## Запуск

### Участнику

Генерировать данные не нужно. Достаточно открыть готовые CSV либо SQLite-файл.

Пример запуска ноутбука из корня проекта:

```bash
python -m pip install -r requirements.txt
jupyter lab notebooks/starter.ipynb
```

Если Jupyter не установлен, данные можно анализировать любым другим инструментом.

### Организатору

Для повторной генерации набора из корня проекта:

```bash
python scripts/generate_data.py
```

После генерации необходимо запустить эталонный анализ и сверить фактические диапазоны с `organizer/ANSWER_KEY.md` и `organizer/reference_results.json`.

## Контроль перед мероприятием

1. Проверить открытие всех CSV и SQLite на Windows и macOS.
2. Убедиться, что starter notebook использует относительные пути.
3. Прогнать кейс на внутреннем аналитике с лимитом 60 минут.
4. Сохранить резервную копию пакета участника.
5. Не включать закрытый каталог `organizer/` и генератор в раздаваемый архив.
